# Organon 论证

本文是[英文哲学正本](../PHILOSOPHY.md)的非规范性配套说明，辨析其关系、根据与限度，不增加哲学义务。[中文哲学](PHILOSOPHY.md)及本篇与各自英文版本对应；解释出现差异时，以相应英文文本为准。[English rationale](../docs/rationale.md)。

第 1–5 节说明当前结构、理由与情境，第 6–7 节区分哲学约束与情境性的应用选择。这些示例展示判断，不是规定工作流程，也不证明普遍正确性。

## 2. 采纳理由及其限度

### 2.1 承诺与反对意见

以下在 Organon 选择的“跨体系的生成与判断哲学”目标下，说明采纳各项承诺的理由。这些是支持该立场的论证，不是普遍必要性的证明，也不向核心增加义务。

| 承诺 | 采纳理由及前提 | 反对意见与限度 |
| --- | --- | --- |
| 自超越 | 珍视更广的理解和构成可能，为不将当前构成视为终点提供理由。这将其拓展视为值得追求，而不认为仅仅允许变化就已足够。 | 拓展可能代价高昂，或与其他价值冲突。本承诺不将其置于一切竞争目标之上，也不要求每次行动都改变。其价值是采纳的立场，不能仅由体系增长来确立。 |
| 自洽 | 若判断要共同引导检验与构成，在相同条件下要求互不相容的结论，就会妨碍这种共同引导。这为审查判断的相容性提供理由。 | 体系可能遇到未解决的张力或冲突证据。区分条件、限定主张或撤回判断可以处理这些情况；自洽本身既不选出正确判断，也不证明其前提。 |
| 反身 | 体系的方法和原则可能参与造成它归因于其他对象的错误。将相关要求用于它们，使这些错误来源可以接受纠正，而不因它们属于自身就获得豁免。 | 自我检验可能有偏差，也不能确立自身的充分性。反身保留适用条件，不要求无尽的复核链或特定的独立复核机制。 |
| 根据 | 当判断引导理解与构成时，可辨明的理由使其支持及限度能够受到质疑。相称要求约束超出这些理由的主张。 | 说明根据可能不完整或代价高昂。不同主张需要不同检验，不要求共同的数值测试。起始价值承诺不必证明每个起始前提，但宣布承诺也不使质疑得到解决。 |
| 实现开放 | 若选择要服务于明确的目标、价值与约束，身份或地位本身并未说明它们与该选择的相关性。这为保留关于充分理由的额外限制提供理由。 | 延续性、传统及身份可以对明确采纳的价值具有意义。它们并非被禁止，但其联系、限度与取舍仍须检验。这一立场不能仅从比较表现的能力推出。 |

这些理由仍接受根据所要求的质疑。辨明每项承诺的作用，不证明它们合在一起是完备的、组织方式唯一，或对所有体系都有约束力。具体应用提供进一步的目标与价值；本哲学不规定它们的普遍排序。

### 2.2 应用中的能力标准

原核心将理解并说明方法形成或改写的根据与限度，规定为方法生成能力的必要条件。当前核心撤回这一定义的统一适用。可靠产出、理解和解释可以作为不同主张接受评价，而不为所有体系规定同一种能力层级。

即使体系不能解释其内部过程，外部证据仍可支持某项明确的能力。反过来，可靠产出本身未必支持理解该过程的主张。应用可以要求这种理解和解释，但须明确提出，而不能归因于核心。修订定义会改变被评价的主张，不能追溯性地确立原主张。

本仓库保留对方法修订的说明及相关变化中的检验，因为所选方法应使拟议变更可供审查。这一理由支持情境性的方法要求，不构成生成能力的普遍测试。相关变化保留方法的适用条件，不是对普遍迁移的任意要求。形成新方法和改写既有方法都可以接受评价，不要求以增加抽象层次或固定文档格式作为能力证据。

### 2.3 检验工具

度量可以使某些差异可比较，重复检验可以审查稳定性，Harness 可以组织检验条件。例如，软件 Harness 可以在指定条件下运行更新后读取的序列，而研究团队可以比较对访谈叙述的解读。每种选择都需要情境理由。这些示例不改变核心的限度：三者不是普遍必然链，未复现的观察可以提供有限支持，随机结果不必逐次相同。

### 2.4 分析方法的根据

[原则性审查 skill](../skills/organon-core-principled-review/SKILL.md)明确所选的审查责任，并集中维护其定义。它意在暴露较少结构化的审查可能遗漏的重大缺口、缺乏支持的主张及替代方案。这一目的为尝试并检验该方法提供理由，不是六个维度足以应对所有任务的证据。该方法本身仍接受核心所要求的质疑，包括对其覆盖范围与成本的质疑。其发现须说明所用标准：对象自身的承诺、选定的比较基准与审查方法的约束彼此有别。在审查中应用 Organon，不代表对象已经采纳它；方法偏好本身也不确立核心冲突。普通的针对性评估和措辞修正不必承担完整审查的负担。

本方法采用条件性的简约偏好，不声称简约确立真实性。[Stanford Encyclopedia of Philosophy 关于简约的讨论](https://plato.stanford.edu/entries/simplicity/)区分原则或假设的复杂度与所假定的实体种类；减少前者可能增加后者，反之亦然。该讨论也区分采用某种工作理论的理由，与相信它更可能为真的理由。这些区别支持明确比较对象及相关约束，而非以更短的措辞或更少的术语作为决定性依据。所采纳的审查仍是情境性的方法选择，不是额外的核心义务，也不证明较简单的候选就是真的。

## 3. 删除检验

| 暂去一项 | 被删去的明确要求及其与其他条目的区别 |
| --- | --- |
| 自超越 | 其他条目可以约束判断、能力主张和实现取舍，却不单独要求以拓展生成可能为内在取向。要求能力主张获得支持，本身不要求珍视能力拓展。 |
| 自洽 | 不再单独要求同时持有的判断在相同条件下相容。根据对支持关系的审查与全体判断的共同成立需要区分，不能仅因每个判断分别提出了理由就认定整体一致。 |
| 反身 | 根据已经涉及原则与判断，但没有单独规定相关生成原则也同样约束这些原则自身的形成和修订。删除反身会失去这一完整的自我适用要求，而不意味着所有自我检验内容都消失。 |
| 根据 | 总纲仍有自我检验和对改善根据的要求，却未单独规定各种主张的根据须可说明、接受相称检验，以及支持须与主张的强度和范围相称。 |
| 实现开放，即根据中的选择条款 | 仍可审查选择的一般理由，却失去名称、惯例或既有地位本身不足以确立优先性的明确立场。 |

删除检验辨析各项的独特贡献与重叠，不宣称完成形式逻辑上的独立性证明。表中“失去”指相应要求不再被该条明确规定，不断言在任何附加前提下都不可能由其他内容推出。

## 4. 情境辨析

以下情境区分当前要求与具体应用的能力标准。这些情境用于审查哲学含义，不是体系必须执行的工作步骤。

| 情境 | 判断与边界 |
| --- | --- |
| 体系有理由保持现有方法，同时保留理解和改变方法的取向 | 稳定不直接违反自超越；保持取向也不足以证明实际能力已经增长。 |
| 体系修订原则并撤回旧判断，不再同时持有两个矛盾判断 | 改变观点不直接违反自洽；仍须判断修订是否有充分根据。 |
| 体系的推论相互一致，但依赖错误前提 | 可以保持内部一致，却没有因此获得正确性。 |
| 两个评价分别重视速度和质量，尚未提出互不相容的结论 | 价值张力本身不构成矛盾；须在相同条件与含义下判断是否真的不相容。 |
| 体系在相同前提、含义与范围内，对同一问题同时断言某判断成立与不成立 | 违反自洽；不能仅以“正在自我超越”取消这个矛盾。 |
| 体系将自身原则作为检验对象，并据此产生新原则 | 回应了反身的对象要求，但未因此证明旧原则或新原则正确，也未自动证明修订充分。 |
| 根据说明完整，但推论只与前提不冲突，并不由前提得到支持 | 可说明性和相容性都不足以确立该推论；根据条目要求审查支持关系。 |
| 一份通过检查的形式证明被用来支持自然语言主张，但编码改变了该主张的条件，或主张与根据之间的关系。 | 证明在其前提和证明依赖下确立编码后的陈述，并不由此确立那项不同的自然语言主张。对应关系的缺陷首先是建模发现，本身不足以构成修订哲学承诺的理由。 |
| 体系将一个价值起点明确作为承诺提出，说明理由、限度和后果 | 可以作为价值承诺接受审查；不因缺少量化结果而直接否定，也不能将其冒充经验必然。 |
| 一次尚未复现的故障有可核查记录 | 可以提供相应的有限支持；是否足以支持某一判断取决于记录、主张及其范围，不能一概排除或无限推广。 |
| 随机体系每次输出不同，但在说明的评价条件下表现出稳定特征 | 输出不完全相同不自动否定证据；须审查条件与稳定特征究竟支持什么结论。 |
| 应用区分运用既有方法与形成或改写方法。体系能够解释并在相关变化中运用既有方法，却没有形成或改写方法的证据 | 证据支持已明确的运用能力，不自动支持另一项形成或改写主张。这些能力定义来自应用。 |
| 应用将生成能力定义为在指定任务类别中产出可用新方法。外部证据支持这种能力，但体系不能解释其内部过程 | 缺少内部解释本身不否定已明确的能力。证据须支持所声称的范围，也不自动确立对过程的理解。 |
| 应用明确要求体系理解并解释方法形成的根据与限度；同一个可靠黑箱不能做到 | 可靠产出不满足该应用要求。撤回原有核心统一定义，不会取消明确选择的情境要求。 |
| 能力检验失败后，作者缩窄定义，并声称原主张未经改变就已通过 | 修订后的定义可以支持新的评价，但不能掩盖改变或确立原主张。 |
| 体系将一百份近乎相同的方法文档作为理解与构成能力拓展的唯一证据 | 数量支持数量主张，不自动支持所声称的拓展。仍需能力定义与相关证据。 |
| 既有方案因明确的兼容性或维护条件而得到优先 | 惯常采用的事实不是唯一根据；相关条件可以提供选择理由，仍须按其性质检验。 |
| 方案仅因名称、惯例或既有地位获得优先，没有相关理由 | 实现开放条目判定这种根据不足；开放也不因此要求无条件选择新方案。 |
| 两种实现当前答案相同，但方法能力、成本或其他相关影响尚未被纳入比较 | 只能支持限定范围内的比较，不能直接认定整体等价；应区分尚未检验与不存在差异。 |
| 工坊珍视传统乐器制作实践的延续，说明采用并传授其方法如何服务于这一目标，同时明确资源限制并承认相关取舍 | 保存该实践可以是明确采纳的起始价值。它与实现的联系可以为选择传统方法提供理由，而非仅凭既有地位。某项具体选择是否服务于该价值并符合约束，仍须检验；宣布目标不使所有传统实现自动获得优先。 |
| 某方案原本仅因“历来如此”而获优先，随后把这句话改称“目标”，却未说明所保存的价值、适用限度或相关取舍 | 换名本身没有增加支持。根据仍要求相应说明与检验；这不否定传统或偏好作为起始价值，也不要求无限追溯外部证明。 |

## 5. 对本次重构的自我适用

新增条目不因数量增加而构成改进。根据条目的贡献在于区分根据的说明与检验，并约束对主张所获支持的表述；能力主张现在需要具体应用的含义和相称支持，不再采用原有统一定义；实现开放的贡献在于明确身份或地位不能自行确立优先。这些贡献及其限度可由上述关系分析和情境重新审查。

对本文自身的审查同样区分哲学承诺、推论和经验主张。公开承诺不提供自我证明；说明某项有独特作用不等于证明其普遍必要；没有发现冲突也不等于完成正确性或独立性的证明。

对已确认措辞、对应章节、链接与文件哈希的检查，用于核对文档一致性及改动范围，不能替代哲学论证。这些检查不赋予工具、治理程序或具体实现以哲学上的权威。

## 6. 跨体系约束

以下是设定的应用情境。其情境假设提供哲学之外的额外前提，结论在这些前提内成立。

### 6.1 研究团队

| 论证环节 | 应用 |
| --- | --- |
| 主张 | 团队可以通过修订访谈叙述的分类方法，改善解释参与者为何放弃某项服务的能力。 |
| 额外前提 | 团队重视解释性理解，希望分类修订可供审查，并将参与者叙述视为有情境的证据。团队拥有经同意取得的访谈材料，人员时间有限，现有分类对每段叙述只赋予一个原因。预期主张涉及受访参与者，材料不足以确立总体中的发生比例。 |
| 推论 | 自超越支持对分类修订保持开放，不要求追求新奇。根据要求区分参与者报告与团队推论，并限定推广范围。自洽要求解决相同定义下分类不相容的问题，或说明定义发生了变化。反身将审查延伸至分类方法及其修订。团队区分熟练编码与修订方法的能力，其明确的可审查性目标要求说明修订理由。 |
| 反例 | 一段叙述同时涉及成本和可及性障碍，并明确说明了二者如何相互影响。单标签方法丢失了这一被叙述的关系；增加标签却不说明这些标签区分什么，也可能仅增加词汇。修订方法允许多个原因，并记录叙述中说明的关系。为检验修订，团队比较两种方法在该叙述及其他相关叙述中分别保留了什么，包括只说明一个原因的叙述。编码者意见一致本身不确立解释正确。 |
| 结论 | 修订具有具体的潜在贡献：保留原分类遗漏的叙述关系。保留这些报告不确立现实中的因果关系。对修订的解释及相关变化中的检验，可以支持“团队在既定目标下改善了分类方法”这一有范围限制的主张；标签数量本身不能。在实现开放下，共同讨论可能适合小型探索团队，分别形成初步解读可能有助于审查共同的解释偏差。二者的成本和证据限度不同，两种选择都须给出与该研究相关的理由。软件 Harness 和 agent skill 都不是该哲学的必然推论。 |

### 6.2 软件系统

| 论证环节 | 应用 |
| --- | --- |
| 主张 | 服务团队可以通过纳入底层数据变化，改善比较两种读取实现的方法。 |
| 额外前提 | 服务要求后续读取返回最近一次已确认的更新，并满足指定延迟预算。团队还要求评价方法的修订可解释，并在相关变化中接受测试，使审查者可以评价其贡献。候选为直接读取与缓存读取。当前比较使用未变化的数据，显示答案相同且延迟合格；尚未检验更新后的缓存失效处理。这些是应用要求，不是 Organon 对所有服务的要求。 |
| 推论 | 根据将现有比较限定于数据未变化的范围。自洽不允许同时宣称规定的新鲜度保证，又在同一保证下接受旧数据。自超越支持在评价范围遗漏相关条件时改进评价方法。反身要求审查该方法对自身覆盖范围的主张。团队的可审查性要求涉及解释为何更新后读取是相关变化，以及增加该情境如何改变可获得的支持；这是应用前提，不是核心统一的能力标准。 |
| 反例 | 两种候选都通过原比较，但其中一种在已确认更新后仍返回缓存旧值。局部答案一致没有确立整体等价。修订方法对两者比较更新后读取的序列，并保留数据不变的情境。通过这些情境仍未覆盖其范围之外的故障、并发条件或负载。 |
| 结论 | 在理解修订后方法的运用方式及限度时，修订可以暴露具体遗漏，并支持以已检验情境为边界的能力主张。实现开放允许因更简单的新鲜度推理而选择直接读取，也允许在延迟条件提供理由时，选择有充分支持的失效处理方案进行缓存读取。输出相同不会消除这些取舍。可执行测试在这里可能有用，而研究团队可能采用解释性比较；哲学不要求相同的方法，也不使本文本仓库成为软件测试 Harness。 |

共同约束涉及理由、范围、一致性、能力主张的支持和自我适用；差异涉及何种证据相关，以及何种方法服务于既定目标。两个例子说明在两种情境中的适用性，不证明对所有体系的完备性。

## 7. 本仓库形式的根据与限度

仓库区分三种地位：核心表达哲学承诺，本文说明论证与限度，skill 提供可修订的应用方法。skill 指令不会仅因引用核心就成为哲学义务。

| 已选择的实现 | 情境理由 | 限度及可能替代 |
| --- | --- | --- |
| 英文正本与对应中文版本 | 已确认的安排为翻译分歧提供单一解释参照，同时支持中文阅读。 | 没有条目确立英文天然优先。英文表述有误时仍需明确修正，正本地位不确立其真实性；其他项目可以选择不同语言。 |
| 以文本为中心的哲学及配套 Lean 工具 | 文本陈述哲学承诺，使其理由和限度可直接审阅。Lean 实现、检查和读者稿提供可复跑的形式化支持。 | 文本本身不确立清晰性或能力。工具通过不确立来源保真、充分根据或哲学正确性。Lean 不是普通哲学评估的前置要求。这些工具是在本库目标和约束下可修订的实现选择。 |
| `organon-core-assess` 与 `organon-core-absorb` | 分开的入口区分当前哲学下的契合性与哲学采纳的理由。absorb 协调反馈、审查、用户决定及必要同步。 | 仅凭契合不足以支持采纳；冲突本身不驳倒修订理由。单独开展的技能与文档维护属于共享流程，不属于吸纳。 |
| `organon-core-principled-review` | 共享六维审查向 assess 与 absorb 提供有根据的发现，也可独立使用。其名称标明方法，不把对象限于体系自身。 | 发现保留所用标准与限度；既不自动确立哲学冲突，也不决定采纳。复用不替代独立初判，也不要求递归审查。 |
| 外部 `grill-me/grilling` | 复用选定的追问方法，在取得可查事实后处理明确的 grilling 请求与实质未决选择。 | 信息齐备的普通评审无需加载它。能力缺失使依赖阶段未完成；无关检查仍可继续。名称或问题本身没有哲学权威。 |
| 独立 agent 在查看作者候选前先形成判断的交叉复核 | 分别形成初步判断，意在暴露遗漏，避免立即接受作者的理解框架。这是已确认的复核方法，不是反身的严格推论。 | 不同 agent 可能共享假设与错误，一致不构成证明。其他情境可以采用人工或其他复核结构；缺少独立 agent 时，本库所选交叉复核仍未完成。 |
| 方法修订的说明及相关变化中的检验 | 本仓库追求可供审查的变更：说明修订并检查相关变化，有助于在新文本之外评价所声称的贡献。 | 这些是情境性方法要求。完成说明或测试不确立普遍能力等级，也不证明已检验范围之外的改进。 |
| 有界迭代记录与每次判别固定基准 | 明确前提、差异及未决事项，有助于追踪支持关系，避免修订候选暗中改变判别自身所用的标准。 | 记录完成本身不构成改进证据。本库哲学变更需要用户明确决定，这种权限安排是情境选择，不是哲学定理。 |

自我适用因此也包括检验这些方法及其所宣称的收益。有用的方法修订需要可辨识的贡献、理由及相关变化中的检验。缺少新增支持的反复一致不会增强主张；根据不足或分歧未解决，可以成为以有限结论结束一轮迭代的理由。不能将越来越长的复核链视为证明。

当哲学承诺改变实质判断、约束自身主张，并引导不同体系中有根据的取舍时，仓库的哲学性质获得支持。目录结构、一组 skill 和复核循环本身不能确立这种性质。[skill 验证情境](../skills/references/validation.md)审查所选应用方法，其结果不能证明哲学普遍正确。
