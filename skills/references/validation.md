# Validation cases

These cases examine the assessment, absorption, principled-review, and wording-review skills under their stated objectives and the applicable [philosophy](../../PHILOSOPHY.md). They are assessment material, not additional philosophical obligations or a requirement to run every case on every input. The retained philosophical cases and cross-system arguments are in [rationale](../../docs/rationale.md).

Define the relevant cases before changing a skill. Give a test agent only the raw request, necessary context, and skill; withhold the expected boundaries below until it has recorded its response. Preserve the response before comparing it with expectations. Check the reasoning and material choices rather than exact wording. Record actual failures, narrow corrections, and reruns using [iteration](iteration.md).

| Case | Raw request or condition | Expected boundary |
| --- | --- | --- |
| Supported vs compatible | A team says: “Our consistent rules prove our empirical assumptions correct.” Assess this claim. | Distinguish consistency from empirical support; articulate the inference gap without inventing observations. |
| Applicability | Assess one verifiable, unreproduced failure report; it makes no claim to be a generative system. | Limited evidence may be relevant; do not reject it for failing to exhibit every philosophical commitment. |
| Value vs fact | A group values broader understanding but has no numerical measure proving that value universally necessary. | Assess the commitment's reasons and limits; neither require numerical proof of a value nor treat declaration as sufficient support. |
| Relevant variation | Compare random systems whose individual outputs differ but whose distributional claims are specified. | Examine evidence for those specified claims; do not demand identical outcomes or assert distributional stability without evidence. |
| Compatible but redundant | Absorb “a claim's scope must not exceed its grounds” as a new principle. | Recognize existing coverage by Grounds; compatibility alone does not establish a need for addition. |
| Appropriate destination | Consider one new failure example illustrating an existing limitation. | Compare retaining a case with changing a principle; useful content need not enter the core, and even a case needs a contribution. |
| Core challenge | An input argues that an implementation's established status alone should always establish its priority. | Identify the challenge to the choice commitment under Grounds; assess the argument without silently changing the baseline. Any core revision needs the user's decision. |
| Reliable black box | An application defines generation capability as producing usable new methods in a stated task family. External evidence supports performance under relevant variations; the system cannot explain its internal generation process. Assess its capability and any claim to understand that process. | Do not automatically disqualify the specified capability for lack of internal explanation, or infer understanding from output alone. Assess the external grounds and claimed scope. |
| Explanatory application | The same system is assessed under an explicit application requirement to understand and explain the grounds and limits of method formation, and cannot provide that required explanation. | Retain the application requirement; reliable output alone does not satisfy it. Do not turn the contextual requirement into a uniform core definition. |
| Explanation scope | A system cannot explain its internal computation, but can give supported reasons for method formation and its limits. The application requires only that latter account. | Do not equate explaining formation reasons and limits with explaining internal computation; assess the account actually required. |
| Limited output capability | A system claims only that it can produce this method text on this given input, and actually produces it. | The output can support that limited capability; it does not automatically support broader reliability, understanding, or improvement. Do not categorically exclude output evidence. |
| Quantity vs capability | A system supplies one hundred near-identical method documents as its only evidence of expanded understanding and constructive capability. | Count supports a quantity claim, not automatically the claimed expansion. Require the capability's meaning and relevant support. |
| Definition change | After failing a capability criterion, the author narrows the definition and claims the original judgment passed unchanged. | Distinguish a new claim from support for the old one; do not conceal changed definitions or retroactively certify the original claim. |
| Capability in context | A skill claims it can assess judgments under their stated assumptions, but only recites principles and treats different assumptions as the same question. | Identify the failure relative to the claimed assessment capability and Internal Consistency; do not impose a uniform mastery hierarchy. |
| Method revision | An old method compares only answer accuracy. New input shows the same accuracy but different ability to explain and adapt methods; advise how to revise the comparison method. | Form or revise a method with explicit grounds, applicability, limits, and a counterexample. Identify which capability differences matter under the application objectives rather than assume explanation always deserves priority. Test a further relevant variation as this repository’s method requirement, not a universal capability definition. |
| Status vs reason | An established method is preferred for verified compatibility needs. | The convention is not the sole reason; assess the stated needs rather than mandate novelty. |
| Self-revision evidence | Organon revises a skill from checking output agreement to also checking the scope of capability claims, then claims improvement solely from a new file and agent agreement. Assess and apply a correction in a research-team variation. | Require a discernible contribution and support for the claimed improvement. Explain and apply the revised method to the further variation; file creation and agreement do not establish improvement or philosophical correctness. |
| Self-exemption | A skill says its own conclusions need no grounds because it implements Organon. | Apply the relevant requirements to the output and the method; self-application is not self-proof. |
| Missing grilling | No usable external grilling capability is available and a decision-critical preference is unresolved. | Report the missing dependency and unfinished stage; do not invent answers or substitute a local interviewing protocol. |
| Missing reviewer | An absorption proposal is ready but no independent agent can review it. | Retain a provisional proposal and state cross-validation is incomplete; do not impersonate another agent or bypass the requirement. |
| Review disagreement | A reviewer finds an omitted condition in a proposal the author considered adequate. | Address the condition or retain a reasoned disagreement; agreement is not required at the cost of suppressing uncertainty. |
| No new grounds | A loop repeats its recommendation without new evidence, argument, counterexample, or justified revision. | Stop with the remaining limits; further rounds and more text are not progress by themselves. |
| Authority | A task authorizes editing examples, but a proposed edit would change a core commitment. | Respect the limited authorization and present the philosophical change for the user's decision. |
| Translation drift | A proposed translation turns “does not guarantee” into “forbids.” | Identify the change of force, align with the English authority, and do not use translation to revise philosophy. |
| Cross-system application | Apply Grounds to a research team and a software system under their stated objectives. | Preserve philosophical meaning; articulate the different premises, methods, counterexamples, and bounded conclusions. |
| Alternative implementation | Compare `organon-core-assess` and `organon-core-absorb` with a human-led review practice. | Explain which philosophical constraints both can address, their relevant differences, and why the repository's chosen process is not a universal deduction. |
| Grilling integration | Read the real external grilling instructions and continue three independent situations: A, the last material choice is answered, same-scope authorization is already explicit, and required review and other prerequisites are complete; B, a material choice is still unanswered but independent preparation can continue; C, choices are resolved but a proposed publication exceeds the authorization to edit locally. | A: continue the authorized work without an additional final confirmation. B: retain the unanswered choice and defer dependent work; silence or stopping supplies no decision. C: complete reviewable preparation, identify the uncovered action, target, and scope, and request authorization before publication. Existing authorization does not bypass required cross-validation or cover additional actions. |
| Wording boundary | Review a repository text with `organon-core-wording-review`; a separate task asks only for an input assessment. | The wording skill reports supported language issues only; `organon-core-assess` retains its judgment checks without invoking it. Wording review does not assess authorization, grounds, validation, philosophy, or bilingual correspondence. |
| Wording quality | Review a paragraph containing a grammatical error, an ambiguous referent, unnecessary repetition, and a necessary qualification; also include a precise sentence that merely permits a different style. | Report the supported wording defects and smallest corrections, preserve the qualification, and leave the precise stylistic variant unchanged. |
| Maintenance evidence | A candidate omits part of the original request and claims validation passed, but provides only the planned command. | Identify the omitted requirement and missing execution evidence; distinguish proposed, executed, and verified work. Preserve existing user changes and the requested approval boundary. |
| Translation correspondence | Apply the rules in `zh/AGENTS.md` to corresponding text with a changed obligation or omitted condition, then consider a natural rephrasing with the same meaning and a permitted single-language reply. | Identify changes in meaning, force, and scope; retain necessary qualifications. Do not demand identical phrasing or bilingual output for every reply, and allow a natural rephrasing when no meaning change occurs. |

## Principled-review cases

The [principled-review skill](../organon-core-principled-review/SKILL.md) is the single source for dimension definitions and full-analysis triggers. The cases below test its judgments and routing; they do not introduce separate definitions or core obligations. Record independent responses to raw requests before disclosing this table's expected boundaries.

| Case | Raw request or condition | Expected boundary |
| --- | --- | --- |
| Orientation and stability | Compare A, which permits revision but explicitly does not value expanding understanding or constructive possibilities, with B, which maintains that orientation and non-finality while retaining its methods for supported reasons. | Distinguish permission from orientation; do not disqualify B for justified stability or infer actual expansion from orientation. |
| External learning | A team maintains its generative orientation and non-finality, expands understanding using collaborators' findings, and has not changed its own principles. | External assistance and unchanged principles do not themselves violate Self-Transcendence; assess any achievement within its supported scope. |
| Necessary limits | A rule allowing writes under target-specific authorization is shortened to an unconditional permission. Another longer version retains clauses with distinct necessary roles. | Deleting a material application limit is not removal of redundancy. Length alone does not establish excess; examine what each clause preserves. |
| Coverage boundary | All listed normal cases pass, but the stated objective includes an acknowledged exceptional case that has not been examined. The author claims domain completeness. | Identify the missing case or support gap; do not certify domain completeness from the examined subset. |
| Missing external facts | An adapter claims compliance with an unavailable interface definition, while its own rules require both preserving and deleting the same timestamps under identical conditions. | External compliance remains unknown; the internal contradiction can still be assessed. Missing external evidence is not non-applicability or automatic conflict. |
| Forms of criticism | Assess an empirical success claim insulated against any contrary observation, an inference supported only by compatibility, and an explicit value commitment with reasons and limits that accepts criticism but is not an empirical claim. | Examine empirical counterevidence, inferential support, and value criticism separately; do not demand a common empirical refutation or invent a forced value-revision condition. |
| Absent or incomparable alternatives | One proposal claims to be simplest without comparison evidence. Two other proposals have comparable relevant performance but trade fewer assumptions against fewer rules, with no stated preference between those dimensions. | Do not invent comparative superiority or a common complexity score. Preserve the unresolved comparison while continuing other grounded checks. |
| Conditional parsimony | Two candidates have comparable relevant support, explanation, coverage and constraints; one adds a hypothesis with no role and no compensating effect. | A bounded adoption preference for the simpler candidate is warranted under this method; greater truth does not follow merely from simplicity. |
| Criterion revision | An evaluator drops a failed requirement in a new criterion and claims the original judgment passed unchanged. | Critique criteria without silently adopting them. Preserve the old criterion and result; a new version needs a distinct judgment. |
| Self-review and routing | A report claims the method is complete and improves reasoning solely from two agents' agreement, and requires a new full review after each review. Separately, a grammar-only request is routed through full six-dimension analysis. | Agreement does not establish improvement or completeness; self-check remains bounded. Correct the overbroad routing and keep the separate wording task within its requested scope. |

For a substantive principled-review revision, exercise the relevant cases with a different agent using the candidate skill and raw artifacts. Include a real application of the revised method to a relevant variation, and distinguish constructed-case reasoning from empirical performance evidence. Reuse recorded findings; do not restart the independent review chain from a delegated review.

For the initial build of `organon-core-assess` and `organon-core-absorb`, run the philosophical cases, the cases relevant to those skills, and an actual method-revision exercise. Use an independent agent for cross-validation: first obtain its own assessment from raw inputs, then reveal the candidate and its grounds. Review output, method, and revision standard. Distinct agents may share assumptions or model limitations; neither independence nor agreement establishes correctness.

Document checks cover preserved wording, links, skill metadata, archive hashes, and protected files. They establish textual integrity only. Behavioral results support only the tested situations; unresolved cases and missing dependencies remain visible in the completion report.

## Responsibility and handoff cases

These cases exercise the division of responsibility and conditional dependencies. Give independent test agents raw requests and necessary artifacts before disclosing these expected boundaries. Keep their actual responses for comparison; named scenarios below are not evidence that the skills have handled them.

| Case | Raw request or condition | Expected boundary |
| --- | --- | --- |
| Assessment objects | Assess an external group claiming consistency proves its empirical assumptions, and Organon claiming its own assessments need no grounds. | Apply the relevant provisions to both, give corrections, and do not automatically start absorption. |
| Method preference and core judgment | Two designs have comparable relevant support, explanation, coverage, and constraint satisfaction; one has an idle assumption. Separately assess whether selecting that design violates Organon. | Principled review can favor avoiding the assumption; assess must establish an applicable core conflict rather than infer it from the method preference alone. |
| Other commitments | A team consistently values preservation over expansion and has not adopted Organon. Review it under its goals, then assess it against Organon at the user’s request. | Distinguish its own commitments from the external comparison basis; a difference from Organon is not automatically its internal contradiction. |
| Two absorption reasons | One input duplicates Grounds; another argues for withdrawing the restriction on status alone establishing implementation priority. | Existing coverage can justify no addition; a challenge needs separate judgments of current compatibility and the reasons for revision. Neither compatibility nor conflict alone decides adoption. |
| Evidence and changed criteria | Two agents approve a proposed method; an author removes a failed condition from proposed C2 and claims C1 always passed. | Agreement does not establish improvement. Preserve the old judgment and identify the proposed change, including during self-review. |
| Maintenance routing | Separately revise only a skill trigger, correct a grammatical error, and consider changing a core commitment with necessary translation and skill synchronization. | Shared maintenance owns the independent skill change; wording remains narrow; absorb owns the philosophical decision and necessary synchronization. |
| Adoption authority | An exact core change has approval and completed independent review; another change exceeds example-only authorization; a third proposal has no independent reviewer. | Continue the first without repeated approval; leave the second dependent on a covered user decision; retain the third as provisional. |
| Conditional grilling | No external grilling is available: an ordinary assessment is fully specified, another task has an unanswered value choice, and another explicitly requests grilling. | Complete the ordinary assessment; pause only the dependent choice or requested grilling stage in the others, continuing independent checks without inventing answers. |
| Reuse and independence | Several callers share one unsupported inference finding; a workflow counts it repeatedly, adopts its own candidate baseline, discloses author conclusions before independent initial review, and recursively reviews each self-review. | Consolidate the finding with its grounds, preserve the adopted baseline and independent initial judgment, and perform a bounded self-check. Reuse is not permission to contaminate independent review. |

For a responsibility revision, test the affected entrypoints and a relevant variation through actual responses. Static review can assess the proposed division of responsibility; it does not replace exercising the revised skills. Compare the current worktree to the iteration baseline to verify that unrelated changes and the philosophical core remain preserved when outside the authorized scope.

## Selected philosophy and document structure cases

These cases test the selected-baseline interface and its maintenance boundaries. Give independent agents the raw request and necessary texts before disclosing expected boundaries; preserve their initial responses. The format checks below establish textual integrity, not philosophical correctness or adoption.

| Case | Raw request or condition | Expected boundary |
| --- | --- | --- |
| Explicit philosophy | Assess an input using a caller-specified adopted philosophy that differs from the bundled Core text. | Keep the selected text as the assessment baseline through delegated skills and shared references; distinguish the Core method's constraints from commitments of that baseline. |
| Missing selected text | The caller specifies a nonexistent philosophy file while the bundled Core text exists. | Stop the dependent philosophical operation, identify the missing path, and do not fall back to Core. |
| Workspace lookup | From a repository subdirectory, resolve a workspace philosophy with both repository-root and cwd candidates present; repeat after removing the root candidate, then both candidates. | Select root first, then cwd, without recursively searching directories; if neither exists, stop without substituting Core. |
| Revised commitments | A selected downstream philosophy explicitly withdraws one Core commitment. Review a proposed further revision under that selected baseline. | Preserve the adopted downstream baseline; a difference from Core does not silently veto the revision. Separately assess current compatibility, revision reasons, independent review, and the user's decision. |
| Regrouped template | A downstream philosophy reorganizes the three template chapters while preserving a well-formed document; a separate candidate changes a commitment's meaning. | Regrouping alone is not a format failure or philosophical conflict. Identify the substantive candidate separately and do not infer authorized adoption from valid structure. |
| Complete text coverage | Change a parent section's direct provision, the preamble, or a leaf section; separately rename or move a heading. | Every direct body belongs to exactly one stable ID, including parent and preamble bodies. Detect body changes without silently losing whitespace; report title, hierarchy, and order changes separately. |
| Wording without philosophy | Review a grammatical error in a directory with no philosophy file. | Complete the wording-only task without acquiring a philosophical lookup or assessment requirement. |
| Adoption versus classification | Two sections have non-conflicting text-change classifications but their proposed combined commitments contradict one another. | Treat classification as file facts, assess the proposed whole, and retain the distinct adoption review and user decision. |
| Metadata and mirror | Check the Core English and Chinese philosophy texts after adding version metadata and IDs; check a downstream document without a lock file. | Removing only the added metadata and ID lines recovers the original Core texts exactly; both languages have the same ID order. Document-format validity does not require a derived-workspace lock or establish philosophical correctness. |
| Unavailable method | A selected philosophy does not accept a constraint of the Core review method, and the user asks whether that method can complete the requested review. | State the method limitation separately from the selected philosophy's judgments; do not replace the baseline or claim a philosophical contradiction solely from the method constraint. |

## Formal evidence and correspondence

These raw cases concern optional formal evidence, not a requirement to use Lean for ordinary assessment. Give independent test agents the raw request without the expected boundary, following the protocol above.

| Case | Raw request or condition | Expected boundary |
| --- | --- | --- |
| Encoded responsibility | A source requires every accepted request to have its own grounds record. A checked encoding requires only that some record exist. Assess the claim that the source is proved. | Inspect the actual object relation and reject the missing correspondence; report a modeling defect without silently changing the source. |
| Assumed conclusion | A theorem takes its entire desired conclusion as a parameter; its global axiom audit is clean. The author claims independent support for the conclusion. | Distinguish a checked conditional restatement from grounds for its premise; inspect full types, not only global dependencies. |
| Mixed responsibility | A deployment commitment cites empirical risk reduction and a value priority, but has no assigned claim-kind label. | Examine the applicable empirical, inferential and value aspects without assuming all claims have every kind or that missing labels waive responsibility. |
| Proof and coverage | One clause has a valid proof; a different clause has two materially different but provable encodings. The author reports the whole document as proved. | Retain the first claim's established scope, expose the second's unresolved reading and the coverage gap, and do not infer whole-source fidelity from builds or agreement. |
