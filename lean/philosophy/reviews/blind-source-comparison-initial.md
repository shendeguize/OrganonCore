## 关键判断

1. **有限模型不是一般能力。** `Integration.World = Candidate` 只有 identity/successor。观察 input 0 能识别 identity，所以全输入能力随实现定义推出。这是有效的封闭模型推理，不是从单次测试归纳所有程序。T02 的这一共享能力/预算/观察/选择部分是真实交互，单独通过；拒绝该家族的原因是其他冻结分支未齐。
2. **规范接口不是现实履行；但也不能丢掉规定的对象。** `Reflexive` 保留 owner/applicable 条件和两种活动；其 `Performed` 只是 pair 会员。作为明确规范覆盖投影可以接受，不能据此表示实际程序已运行。T13 另要求形成理由、适用域考察和修订理由，当前对象没有这些内容，故该分支未完成。
3. **价值承诺不必被证明真，与理由必须对应立场是两回事。** 盲读已编译出恒 False commitment 的 ValueProcedure/Grounds；这本身不要求所有价值立场成为事实，更不是 Lean 推出 False。实质缺陷是 `ValueProcedure` 不读取 commitment/starting，替换任意不相关 commitment 不影响通过性。它只检验理由推出另一可任意指定的 consequence。T15/T25/T27 需要实际理由与当前立场的联系，不能由这一接口自动得到。修正应允许非演绎价值理由和未证起点，而不是强行要求理由逻辑证明承诺。
4. **已有有限价值见证仍可通过。** T18 的 switchPosition 把所选 true 选项的成本/收益作为具体理由，起点另证可满足，批评世界有响应，并证明空理论不推出承诺。这一有限程序相容性目标成立，通用接口的较弱性不自动否定该具体存在见证。
5. **事实优先命题与额外选择规范不可混同。** T23 当前证明“两个 status facts 不推出 selected=identity”；冻结问题是一般评估责任不推出额外的反 status-only 优先规范。现有反例没有独立可变 choice policy，也没有一般责任履行而该额外规范失败的同一模型，因而不能算规范独立性完成。
6. **Grounds 条款自身不同于一次能力的 Grounds 满足。** `commitmentClaim .grounds` 是固定 `OwnCapabilityDuty capability [capabilityFacet]`。其观察理由支持该能力，却不是 Grounds 条款采纳/适用要求自身的理由。`existingPhilosophy` 也仅修改 identityImpl.name，没有连接到本模型的采纳政策或原则。因此 T25 的这些反身对象尚未对应来源。
7. **不能用并列标签替代同一对象。** T06 中外部资源求和确实依赖三个 Option，但没有把该算法与 Generative 政策的系统执行/状态相连；稳定阈值没有连接到应用约束/动作；自述仅 `expanded=expanded`。T07 也尚未将通用 support 定理实例化为同一 before/after、基线、条件和成就主张。已有库存非扩展反例保留，其余分支须实际补齐。
8. **不用额外提高已冻结有限例子的标准。** T08–T12、T16–T20、T22、T24、T28 的通过范围依各实际数学定义限定：例如 Q 可为空、解释力代理只是数值等同、procedure 只看末项、Trial 的复现只看 setting、非经验不等于不可计算。这些界限不能被宣传性名称扩大，但不自动推翻冻结的有限反例/接口后果。
